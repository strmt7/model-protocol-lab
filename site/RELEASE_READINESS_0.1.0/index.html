    Release-readiness report — model-protocol-lab 0.1.0¶

    Date: 2026-10-16

    Addendum 2026-10-17: historical report — the residual risks § carries its original 2026-10-16 numbers and wording (e.g. 6083 tests); see docs/SECURITY.md, VALIDATION.md, and CHANGELOG.md [Unreleased] for the current state (4481 tests, both runners agree; SECURITY.md residuals updated through cycle 132). Residual items marked Retired below stay retired; the remaining risks are still accepted.

    Addendum 2026-10-23 (cycle 201): a three-lane release-readiness audit (packaging, new-user experience, legal/project health) re-checked this report against the tree and found its currency claims stale — the 2026-10-17 addendum above was the last refresh. Current state, measured at cycle 201: 11 CLI subcommands; 59 package source files; test count and coverage as stated in VALIDATION.md (the count moved with cycles 199–201 and is maintained there, not here). The audit's verdict was zero blockers in all three lanes; every should-fix was re-verified against the tree by the coordinator and dispositioned in cycle 201:

    • CHANGELOG gaps for cycles 196–198 (including the user-facing run --precision flag) — fixed: backfilled, and a mechanical gate test now enumerates the CLI surface and the per-cycle range and fails if coverage lapses again.
    • "Pre-Alpha" classifier in the wheel metadata — fixed: Beta.
    • Builds not byte-reproducible; no release procedure — fixed: tools/release_build.py (mtime normalization, sdist tar-metadata normalization incl. PAX time headers, wheel built from the sdist, double build with identical SHA-256 required; verified at cycle 201 with both artifacts byte-identical across two builds).
    • torch unbounded above — fixed: torch>=2.6,<3.
    • [hf] install silently pulls a multi-GB CUDA stack — fixed: README documents the size and the CPU-index route; the quickstart's full-suite step is labeled optional with its expected duration.
    • No documented vulnerability-disclosure route — fixed: docs/SECURITY.md names GitHub private vulnerability reporting (enabled for this repository; verified through the GitHub API).
    • No code of conduct — fixed: CODE_OF_CONDUCT.md.
    • Vendored upstream chat templates without local attribution — fixed: docs/evidence/README.md (sources and upstream licenses resolved against the Hugging Face API, 2026-10-23; MiniMax's custom terms are recorded as custom, not relabeled).
    • No release workflow — fixed: .github/workflows/release.yml (tag-triggered, Trusted Publishing with PEP 740 attestations, actions pinned to API-verified SHAs). It is inert until the owner creates a tag and registers the Trusted Publisher on PyPI — both owner steps, deliberately not automated.
    • No lockfile — partially fixed: pylock.toml (PEP 751) pins the dev environment with wheel hashes; the hf extra is not locked (hashing its wheels requires the multi-GB download), and the residual stands in docs/SECURITY.md.
    • Missing py.typed, thin project URLs, sdist missing the changelog — fixed (marker shipped in the wheel; Repository/Issues/Changelog URLs added; MANIFEST.in).
    • Copyright holder named as a collective — owner decision, no change (CITATION.cff names the author).
    • UPLOAD_TO_GITHUB.md at the repo root — open: obsolete, but the push pipeline cannot delete files; removal is a one-click owner action in the GitHub UI.
    • Error-message nits (a raw parser message after a fixed prefix; "audit sidecar" jargon in one refusal) — accepted: the fixed error vocabulary is pinned behavior; the messages are accurate and traceback-free.

    The dependency license inventory was refreshed from the PyPI JSON API during the audit (2026-10-23): zero runtime dependencies; the hf extra is all-permissive; the only weak-copyleft item anywhere is MPL-2.0 hypothesis, dev-only and never shipped.

    Scope: every item of the release-readiness definition of done, with evidence (commands, dates, counts). Prepared by the autonomous development coordinator across cycles 84–96. No git tag has been created — tagging is the owner's decision.

    10. Final red-team sweep — DONE (cycle 96)¶

    Three parallel adversarial agents probed novel surfaces with executable PoCs (debug REPL + CLI, doctor hostile checkpoints, scoring / diff / emulation modules). Eight genuine findings, all fixed with 20 regression tests (tests/test_cycle96_redteam_sweep.py):

    ID Severity Finding
    R4-1 Medium Lone surrogates crashed strict stream writes (diff-reports stderr, debug REPL session kill) — all four _CONTROL_CHARS sanitizers extended
    R4-2 Medium BaseException from a misbehaving backend escaped the sanitization boundary (core.evaluate, scoring.score_target_logprobs) — now caught, mapped to fixed codes; KeyboardInterrupt/SystemExit still propagate
    R4-3 Medium Raw RecursionError escaped examine_model via deeply-nested safetensors header — now caught
    R4-4 Medium FIFO-swap hang in _read_json / _manifest / _check_weight_headers — new _open_regular_read() (O_NONBLOCK + fstat S_ISREG)
    R4-5 Medium Jinja chat-template memory bomb materializing before the render cap (+1.9GB RSS) — transient RLIMIT_AS around the render; bomb now raises MemoryError with zero RSS growth
    R4-6 Low–Medium portability_matrix raised raw OSError on unreadable second checkpoint — now unavailable
    R4-7 Low Unbounded checkpoint-controlled model_type in output — truncated to 200 chars
    R4-8 Low Quadratic transcript accounting in debug REPL — running counter

    Prior rounds (documented in docs/SECURITY.md): full audit 2026-10-12 (7 findings), red-team rounds 1–3 (1 high + 1 medium + 4 low; 2 findings; 5 findings incl. 2 high), per-cycle sweeps through cycle 95. Total: every finding ever raised has a fix and a regression test.

    Residual risks (accepted, documented in docs/SECURITY.md)¶

    1. torch's +cpu local tag is invisible to pip-audit (manual CVE re-verification on every bump).
    2. No hash-pinned lockfile (CI pip-audit gate mitigates).
    3. ~~_manifest reads weight files twice per run (I/O cost on very large checkpoints).~~ Retired 2026-10-17 (cycle 115): the backend now hashes each weight file once and verifies a cheap stat fingerprint after the load; the double full-hash is gone (documented trade-off in docs/SECURITY.md: a content swap preserving size, nanosecond mtime and inode inside the load window would evade the stat check).
    4. Hostile Jinja templates can still burn CPU inside the render on off-main-thread or non-Unix platforms (same exposure as HF's own apply_chat_template); on Unix, in the main thread, each render runs under a 10 s SIGALRM wall-clock budget (cycle 116) and degrades to "unavailable" on expiry. Template source and rendered output are capped at 1 MB each; memory bombs are capped.
    5. template_diff degrades (not hangs) after a 10s budget on adversarially fragmented inputs.
    6. Do not expose the CLI as a multi-user network service (no auth, tenant isolation, or audit logging — documented operational limit).
