    Payload-serialization probe — design round (ADJUDICATED: NO-BUILD)¶

    Round summary (coordinator #35, design round only — nothing built)¶

    • Tree at main 960b70dcde87 (cycle 211 closed green, 8,402 tests, per the round brief). This round was READ-ONLY except for this doc and the briefs; no suite was run, no push was made, no tag was cut or discussed.
    • Specialists (blind to each other): researcher (~/workspace/agents_out/payloadformat/research.md), red-team A (redteam_a.md), red-team B (redteam_b.md), verifier/claims auditor (verifier.md). All four briefs landed; the verifier resolved every externally checkable claim against primary sources and spot-checked the load-bearing tree citations.
    • Convergence: both red teams independently returned NO-BUILD, and the verifier upheld both verdicts. The coordinator re-executed the load-bearing claims itself (see "Adjudication evidence" below) and concurs.
    • Verdict: NO-BUILD — for the candidate as tentatively framed (run --payload-format: JSON vs plain text vs other encodings of "the same content", verdict flips as headline) AND for the researcher's design as written. The reasons are not implementation gaps; they are defects in the defining claim (see §1). §2 specifies what a resubmission would have to satisfy in full. A resubmission satisfying §2 is a DIFFERENT, narrower instrument and must be reviewed as a new design, not built as "this probe with amendments". Accepting the amendments while keeping the original causal claim does not count as accepting them.

    1. Why NO-BUILD: the fatal defects (each individually blocking)¶

    F1 — "The task payload" is undefined, and the tree gives it incompatible meanings¶

    Placement's payload is a prose fact passage (placement.py:267-283 arm_content); a structured spec's context is prose (structured.py:445-458 render_prompt); a structured spec's answer document is canonical JSON (structured.py:463-480 build_structured_fixtures); shipped user fixtures are instructions, not data (examples/fixtures.json). No module defines a serializable task-data record type. A design that leaves the choice to the builder does not have a population, a scorer, or a headline — underspecification at this level is itself a build-blocker.

    F2 — "The same content" is false across the named encodings¶

    Typing, loss, and parser-dependence change the content before any model runs. Executed in adjudication: json.loads('{"a": 1, "a": 2}') gives {'a': 2} (last-wins); JSON 349 is int while plain-text 349 is str; JSON true/null are boolean/null while plain-text true/null are strings; CSV flattens nesting; XML must choose attributes vs elements. There is no canonical-equivalence theorem for JSON-vs-prose comparable to canonical-form's UAX #15 basis, and prose has no parser to be equivalent under. A content-preserving claim needs, per arm, a frozen byte-exact renderer, a frozen key order, and a lossless value restriction — which the candidate as framed does not supply.

    F3 — "Serialization" bundles at least six simultaneous treatments¶

    Token length, delimiters/punctuation, quoting/escaping, key order, whitespace, and output priming all move together. Key order is already a shipped probe (run --field-order); whitespace is ws_canonical's territory; length/position are needle/distraction/density/placement axes. No paired contrast over such arms attributes a flip to "serialization" rather than to the bundle. The only supportable claim is descriptive pairwise discordance between named frozen renderings, with length and priming stated as bundled, never a causal "serialization changes verdicts" headline.

    F4 — The byte-exact scorer × output-format priming manufactures and hides flips¶

    The verdict is byte-exact with no answer stripping: core.py:797 (exact_match = status == "completed" and answer == case.expected), conjoined with boundary presence in stage cells (experiments.py:9515 pattern). A model answering correctly in the input arm's idiom ({"code": "amber-1234"} on the JSON arm) scores False against a bare expected value; a model failing to parse the JSON arm but guessing the bare code scores True on both. The fixes are closed: parse-then-compare redefines "verdict" relative to every sibling probe and the diff validator's digest identity (the fix canonical-form rejected); outcome-dependent exclusion deflates discordance exactly as field-order's F6 lesson discloses; the scorer-lens ladder has no label-strip operation and cannot rescue JSON-echo answers. The researcher's echo diagnostic beside the headline is necessary but does not cure this: it explains flips, it never rescues them, and the headline still bundles comprehension with priming.

    F5 — Degenerate populations and arms¶

    Single-field cases collapse to punctuation differences (executed: scalar JSON 42 is byte-identical to plain 42; single-field JSON differs from key-value lines only by braces, colon, and quotes). Multi-field populations are already partly owned: field-order owns key order over 15 specs, structured owns output adherence over 9 specs (1–2 fields only — not 1–4, as red-team A misstated; see §4). Whitespace-only JSON variants (compact vs spaced vs pretty) are a whitespace probe under a serialization name. The researcher's multi-record table population is the right shape of answer to F5, but it does not cure F1–F4, and its arm set and headline do not survive (see §2).

    F6 — The researcher's design as written does not survive its own amendments¶

    Credit where due — the researcher already supplies a frozen multi-record population with unique keys and distinct values, frozen field order, a value alphabet plus a four-way byte-divergence assert, and an echo diagnostic beside the headline. What still kills it as written:

    • The YAML arm must go in v1: zero runtime dependencies (pyproject.toml:28, dependencies = []); no stdlib YAML parser; YAML 6.0.1 importing in this VM is an environment accident, not a declared dependency; a hand-rolled mirror parser is new untrusted code whose quoting choices become hidden treatments. TOML has no stdlib writer (tomllib has no dumps, executed); XML escaping rewrites visible text. V1 arms must be stdlib-serializable frozen renderings only.
    • The falsification headline must be downgraded from causal to descriptive pairwise discordance with ONE pre-registered primary pair; the researcher's prose-vs-rest framing plus all-pairs matrix, with placement's floors borrowed without operating characteristics for a four-arm panel, does not survive the k(k−1)/2 multiplicity problem (10 pairs at 5 arms).
    • The prose "control" framing must go: prose is one encoding among others. The researcher says this, then still computes prose-vs-rest first. The decision rule must pick one framing before building.
    • Missing mandatory machinery: a closed-book screen (placement pattern; canonical-form's lack of one is a gap to avoid copying, not a precedent); a boundary-only vs exact-only discordance decomposition; the full selection-vocabulary transplant; per-arm attrition reporting; a frozen fail-closed vocabulary with renderer failure failing the whole stage closed.

    2. Resubmission specification (NOT a build order)¶

    A resubmission is reviewable as a NEW design only if it satisfies ALL of the following in full. Partial compliance is still NO-BUILD. The resubmission's working name must reflect the narrowed claim (a descriptive frozen-renderer discordance probe); do NOT ship --payload-format until the naming audit against USAGE §8.46 passes, since placement's "payload" sense is reserved.

    Monday-morning utility (narrowed instrument)¶

    A prompt-assembly owner, deciding whether to pin one frozen rendering (prose or canonical JSON) in their prompt assembly and re-run template selection under that pinned rendering — before a routine upstream format change silently flips eval verdicts. The readout answers "these two frozen renderings discord on N paired cases on this checkpoint", never "serialization is (in)ert in general", and never anything about weights.

    Arms (frozen, byte-exact, stdlib-only)¶

    • Exactly one pre-registered primary pair, recommended: prose vs canonical JSON as defined by structured._canonical_json (structured.py:336-343: json.dumps(document, sort_keys=True, separators=(", ", ": "), allow_nan=False); default ensure_ascii=True). Executed in adjudication: that rendering is byte-unequal to compact json.dumps ('{"age": 36, "name": "Ada Lovelace"}' vs '{"age":36,"name":"Ada Lovelace"}'), so the canonical form must be pinned by name and by test, never assumed.
    • Every arm is a named total function with a byte-exact specification and a worked example in the resubmission doc, pinned by a test that its output is byte-identical to the doc's example. "Plain text" without such a function is not an arm name; it is a placeholder. Pretty JSON, flow YAML, Markdown lists, and single-record tables are excluded as duplicates, each with the duplicate it duplicates named.
    • CSV stays deferred (loss analysis: CSV flattens nesting and drops types). XML stays deferred (escaping rewrites visible text; no canonical-serialization convention in the tree). YAML stays out of v1 entirely (see F6); it may return only as a separately justified v2 with a declared dependency or a frozen stdlib-only renderer the validator can mirror. No other arms are decision inputs; any further arms are descriptive context only.

    Population and controls (the attribution contract)¶

    • Generated cases only, stage-local, never entering the user's search/held-out Split (canonical-form invariant 3 pattern; Split compares message inputs by NFC key, core.py:193-214, so variant fixtures would collide — no fixture arm).
    • Fresh multi-record tables (4–6 records × 3–4 fields), one key field (unique per table), one answer field, 1–2 distractor fields whose values are distinct from the answer value in every row. Cases whose answer value appears in more than one row, or whose key field is not unique, are excluded pre-generation with counts, never silently dropped.
    • Value restriction (v1, strictest form): flat, string-only, ASCII, stem-disjoint, reader-entailed tables. Answer field is a plain word-number-style code in every arm. No null, no nesting, no duplicate keys, no floats, no non-string keys, no YAML-reserved words (yes, no, on, off, null, ~), no date-like strings, no leading-digit strings. Non-answer fields are string-shaped too. Integers/booleans are a v2 question with a frozen per-arm type-rendering table, not a v1 entitlement.
    • Held constant across arms (each a generator/validator assert): the same record multiset, field values, key field, and answer field; one frozen field order (alphabetical, the structured.describe_schema convention, structured.py:403-443, which sorts properties) in JSON keys, YAML keys (v2), and table columns alike, and the same sentence field order in prose; a byte-identical question and instruction string in the same position relative to the table (question after the table in all arms); a byte-identical output contract ("Answer with ONLY the value." or equivalent, frozen); greedy decoding, the same --max-new-tokens, the same boundary ids, the same seed, the same template family per candidate. Templates are not touched: serialization lives inside the user message content only.
    • No format label in the instruction unless the label choice itself is frozen identically across arms and its confound is stated.
    • Closed-book screen arm (placement pattern, placement.py:374-380 screened()): a case the candidate passes closed-book is excluded from the live populations, with n_screened and n_closed_book_incomplete reported. Without it the headline is dilutable by cases serialization cannot move.
    • Answer-embedding audit: no field name, key, topic token, or neutral sentence shares a 4-character prefix with, or is a prefix of, any expected value (placement's stem-disjointness pin, extended to keys). Reader-entailment audit per case: a reader given question + table must derive the answer uniquely, or the case is descriptive-only. If a resubmission instead reuses shipped specs, it inherits field-order's paired: False flags verbatim — all five: route-alert, route-order, classify-sentiment, classify-urgency, classify-language (verified by grep: 5 paired: False entries, 10 paired: True, 15 specs total).
    • Byte-divergence assert across arms per case, with excluded counts; boundary-containment screen plus audit_special_token_literals (fixtures.py:471) over every frozen renderer output for every family before generation. Screened cases are excluded pre-generation with counts, never silently dropped.
    • Generation/record/payload caps and the generation count at the legal maximum of 24 candidates are frozen in the module with derivations and stated in CLI help (field-order precedent: 15 specs × 4 arms × 24 candidates = 1,440; canonical-form: 2 × 24 × 24 = 1,152; placement: 4 × 24 × 24 = 2,304).

    Scorer pins (binding)¶

    • Headline scorer, named before building: byte-exact verdict per core.evaluate (core.py:797). No stripping, no parsing, no normalization is added to the headline path for this probe.
    • Beside the headline, never rescuing flips into passes: a parsed-value / echo-substring diagnostic (per arm, the share of byte-exact failures whose decoded answer contains the expected value as a substring or as a parsed field value — the echo rate); scorer-lens R1 (whitespace trim/collapse, scorerlens.py:146-153) and fence-strip (:176-187) regrade rates as sensitivities; and the exact-only vs boundary-only discordance decomposition (a boundary-only discordance is a boundary effect, never a serialization effect, and cannot falsify any claim).
    • Expected values are pure ASCII (canonical-form SCORER PIN transplant): decomposable characters live in carrier prose only.
    • If byte-exact and parsed-value scorings disagree, the section prints both and says which question each answers; it must not pick the flattering one post hoc.

    Fail-closed vocabulary (frozen before building)¶

    • Stage details exactly: {cancelled, payload_format_record_budget_exceeded, payload_format_screen_failed}. (The payload_format_ prefix is retained for the stage-detail pattern only; the CLI flag name is still subject to the naming audit above.)
    • Per-cell details exactly: {"", arm_context_exceeded, arm_evaluation_failed}.
    • Model parse outcomes exactly field-order's document_kind set (object / non_object / unparseable / ""), where unparseable means JSON parse failure of the ANSWER only.
    • Model parse failure is scored wrong, never a detail. Any renderer failure, serializer exception, or non-UTF-8 payload degrades the whole stage to {"available": False, "detail": "payload_format_unavailable"} — never to a per-cell verdict.
    • No new verdict words. In particular: no arm_parse_failed, no unparseable as a cell detail for stage-produced inputs, no payload_too_large, no per-arm "not applicable".
    • Per-arm attrition (n_context_exceeded, n_evaluation_failed) printed beside every paired rate; ungated discordance printed as a sensitivity wherever any gating applies.

    Report shape and decision rule¶

    • Headline population: both arms completed AND full-render id sequences diverged (canonical-form invariants 9–10). Three-way report per pair: ids-identical / divergent-concordant / divergent-discordant, with the per-case id_length_delta list (in case order) and max_abs_id_delta. Same-ids verdict flips are recorded as determinism findings (n_same_ids_verdict_flips), never as serialization fragility. A run landing 100% in the ids-identical bucket reads "instrument inapplicable to this tokenizer", never "the model is robust to serialization".
    • Per-candidate classification over the id-divergent paired population, with the resubmission's OWN operating characteristics printed with the verdict (critical splits, power at a stated gap, expected false falsifications across candidates for its panel size). Borrowed floors are forbidden: placement/canonical-form floors (MIN_PAIRED_EVALUABLE = 6, MIN_DISCORDANT = 2, placement.py:172-173) and field-order floors (6 discordant specs + sign test) may not be transferred to a payload panel without that argument. Below the discordant floor the verdict is insufficient — withheld, never defaulted to acquittal.
    • Selection vocabulary transplanted verbatim from canonical-form (canonicalform.py:566-641): a candidate "passes" an arm iff it passes every completed case on that arm; winner_changed only when both arms select and winners differ; winner_abstention_asymmetric for exactly one side selecting; winner_undefined when neither selects or selection is withheld (completed sets differ across candidates or are empty). Selection-vs-abstention is NEVER a winner change. Per-arm accuracy rates sit beside every selection readout; per-arm completion and withheld rates are printed. The per-case discordance classification is the primary readout; the winner headline is secondary and labelled as such. Discordance is never pooled across candidates/templates: per-candidate contrasts only.
    • Records carry digests only (per-arm content digests, token counts, ids_identical, id_length_delta, cells, details — canonical-form record shape). The diff validator regenerates every arm's rendering from its own literal renderer copies and checks each digest plus pairwise digest inequality across arms, plus ids_identical implies equal arm token counts. Reports render counts/rates only, no payload/question/answer text, every payload-derived string through _escape_text (reporting.py:28), never bare escape().

    • No "first" is claimed anywhere in this doc. The contribution of any future resubmission is the combination stated in §2, never priority. No fabricated citation was found in this round (unlike the wave-9 round); the failures found were one unresolved detail, one dropped qualifier, and sloppy line ranges, all handled above by removal or correction.
    • Two 2026 preprints the researcher saw only as search snippets remain uncited and unrelied on; a resubmission wanting them must verify them from primary text first.

    6. What a build cycle must NOT do on the basis of this doc¶

    • Do not build the researcher's four-arm probe, the tentative run --payload-format sketch, or any YAML arm in v1.
    • Do not write a causal "serialization changes verdicts" headline, a prose-control framing, or any new verdict word.
    • Do not transfer placement/canonical-form or field-order floors to a new panel without printing that panel's own operating characteristics.
    • Building, if it ever happens, is a separate cycle, on a fresh design review of a resubmission satisfying §2 in full — and only on a BUILD verdict from that review.
